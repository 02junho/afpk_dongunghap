# 02. 이 방향으로 AI가 잘 활용될 수 있는가

결론: **된다. 단, 좁게 써야 한다.** 좁은 게 이 기획의 강점이다.

## AI가 하는 일 3가지

| # | 일 | 입력 | 출력 | 위험도 |
|---|---|---|---|---|
| 1 | 자유서술 답변의 의미 비교 | 카드 전제 + 답변 A + 답변 B | 전제 대비 편차, A·B 일치 여부, 사유 | 중 |
| 2 | 🔴 건 설계사용 요약 | 카드 + 두 답변 + 판정 | 3줄 요약 | 낮음 |
| 3 | 설계안 문서 → 카드 초안 추출 | md/docx | 카드 JSON 초안 (설계사 검수 필수) | 중 |

## AI가 하지 않는 일

- **계산** — 소득 요건, 한도, 월 상환액, 기한. 전부 규칙 기반 엔진
- **판정 기준** — 허용 오차, 🔴 경계는 설계사가 카드에 적는다
- **재무 조언** — 어떤 문장도 AI가 부부에게 "이렇게 하세요"라고 말하지 않는다
- **자동 반영** — AI가 추출한 카드 초안은 설계사가 확정하기 전엔 앱에 안 들어간다
- **재설계** — 🔴 이후 연동 수치 재계산은 규칙 엔진(`src/engine`)이, 전제를 어떻게 바꿀지는 설계사가. AI가 재설계하면 이 문서의 주장이 무너진다 (10.14 팀 논의에서 확정)

## 핵심 설계: 2자 비교가 아니라 3자 비교

"남편과 아내가 같은 말을 했나"만 보면 틀린다.

> 남편 "2029년쯤" / 아내 "애 낳고 나서"
> → 둘이 다른가? 2029년에 아이가 있으면 같은 말이다.

그래서 **설계 전제를 기준점**으로 둔다.

```
A vs 전제  →  match / minor / major
B vs 전제  →  match / minor / major
A vs B     →  agree / disagree
```

| A | B | A·B | 판정 | 의미 |
|---|---|---|---|---|
| match | match | — | 🟢 | 전제 유효, 부부 일치 |
| minor | match | — | 🟡 | 한쪽이 흔들림. 대화 유도 |
| major | match | — | 🔴 부부 불일치 | 설계사에게 |
| major | major | agree | 🔴 **전제 폐기** | 부부는 일치하는데 설계가 낡음 → 설계사에게 |
| major | major | disagree | 🔴 부부 불일치 | 설계사에게 |

**"전제 폐기"** 가 이 구조의 보석이다. 부부가 싸우는 게 아니라 설계가 현실을 못 따라온 경우를 따로 잡아낸다. 설계사 체면 문제(설계검토 보완 ⑤)가 여기서 구조적으로 해결된다.

## 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 같은 뜻을 다르다고 (오탐) | **설계사**가 "이건 같은 뜻이에요" → disputes → golden set 추가 → 프롬프트 수정. 부부는 판정을 보지 않으므로 설계사가 라벨한다 — 전문가 라벨이라 오히려 낫다 |
| 다른 뜻을 같다고 (미탐) | 🟡 쪽으로 기울이는 프롬프트. 미탐보다 오탐이 낫다 — 오탐은 사용자가 잡는다 |
| 같은 입력에 다른 답 | temperature 0, 구조화 출력, `prompt_version` 저장 |
| 가치관 차이 vs 사실 차이 구분 불가 | AI는 판결하지 않는다. 🟡는 설계사 큐에 안 올리고 다음 라운드에 다시 묻는다(2연속이면 🔴) |

## 부록 3번이 저절로 쌓이는 구조

```
eval/golden.jsonl     답변쌍 + 정답 라벨 (처음 20건, 이의 제기로 계속 증가)
eval/run.ts           현재 프롬프트로 전부 돌려 혼동행렬 + 오탐 목록 출력
judgments.prompt_version   어느 프롬프트가 판정했는지 DB에 남김
disputes              설계사가 "이건 같은 뜻이에요" 누른 기록 (planner_id)
```

프롬프트 v1 → v2로 고쳤을 때 golden set 정확도가 어떻게 변했는지가 그대로 **"AI 비판적 검증"** 증거다. 다른 팀이 "ChatGPT에 물어봤다"를 쓸 때 우리는 혼동행렬을 낸다.

## 솔직한 한계

- text 카드가 5~6장뿐이라 "AI 앱"으로 보이기엔 AI 비중이 작다. → 보고서에서 **의도적으로 작게 썼다**고 먼저 말한다. 환각이 재무설계에 끼어들 자리를 설계로 막았다는 주장이 더 세다.
- 한국어 뉘앙스("좀 무리" vs "감당 가능")는 LLM도 흔들린다. → golden set에 이런 쌍을 일부러 넣어 오탐을 유도하고 기록한다.
