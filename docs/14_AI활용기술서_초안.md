# 14. AI 활용 기술서 (부록) — 앱 부분 초안

> 공모전 양식 「보고서 및 기술서.docx」의 **붙임 4 · AI 활용 기술서(부록)** 칸에 맞춰 앱 부분만 채운 초안이다. 2026-10-27 기준.
> 재무설계 본문(1~6단계 사례)에서 팀이 AI를 쓴 내역은 **팀이 채운다** — 아래에 `【팀 작성】`으로 자리만 표시했다.
> 숫자는 `docs/05_평가기록.md`에서만 가져왔다. 앱 설명 줄글은 `docs/13_제출용_앱소개.md`.

## 양식이 요구하는 것 (확인 결과)

| 항목 | 양식 요구 | 앱이 들어가는 곳 |
|---|---|---|
| 분량 | A4 **3~10매** (본문 7~14매와 따로 셈). **부록을 안 내면 심사 제외** | — |
| 개인정보 | 성명·학교명이 있으면 심사 제외 (본문 유의 사항) | 이름 쓰지 않기 |
| 1. 사용한 AI 도구 | 도구명 · 버전·요금제 · 주요 사용 목적. **빠짐없이** | 앱을 만든 도구 + 앱 안의 AI |
| 2. AI 활용 내역 | 단계별 **주요 프롬프트를 그대로** · AI 응답 요약 · 본인 판단·수정 · 산출물 | 6단계(점검) 행 몇 개 |
| 3. 검증·수정 내역 | AI 내용 · 검증 방법·출처 · 발견한 문제 · 최종 수정 | 판별 AI 정답 대조 결과 |
| 4. 종합 기술 | 가장 유용했던 단계 · AI에 안 맡긴 부분 · 질이 높아진 근거 · **별도 제출 앱이 있으면** 무엇을 풀려고 만들었고 제작에 AI를 어떻게 썼나 | 마지막 항목 = `docs/13` 줄글 |

양식 안내문의 핵심 문장은 "**최종 판단과 책임이 참가자 본인에게 있었다는 점이 명확히 드러나게**"다. 아래 표는 모두 이 기준으로 썼다. AI가 제안하고 사람이 고르거나 거절한 사례를 중심으로 골랐다.

## 1. 사용한 AI 도구

| 도구명 | 버전 · 요금제 | 주요 사용 목적 |
|---|---|---|
| 클로드 코드(Claude Code) | Claude Opus 5.5 / `【요금제 기입】` | 앱 설계 정리, 코드 작성, 자동 점검(테스트) 작성, 화면 점검, 팀 문서 초안 |
| 클로드(Claude) API — 앱 안에 들어간 AI | Claude Sonnet 5.5 / 사용량 과금 | 부부의 서술형 답 뜻 비교(판별), 설계사용 3줄 요약 |
| `【팀 작성: 재무설계 본문에 쓴 도구】` | | |

> 요금제는 실제 결제한 것으로 적는다. 앱 안의 AI는 정답 세트로 잰 모델과 실제 앱 모델이 같다(Sonnet 5.5).

## 2. AI 활용 내역

프롬프트 칸은 실제로 입력한 문장을 그대로 옮긴 것이다(맞춤법 포함).

| 활용 단계 | 입력한 프롬프트 (실제 질문 내용) | AI 응답 (핵심 답변 요약) | 본인의 판단 · 수정 (선택·수정 내용과 그 이유) | 산출물 (본문에 반영된 결과물) |
|---|---|---|---|---|
| 6단계 점검 (앱 — 엑셀로 질문 카드 만들기) | "이거 기반으로 이제 엑셀파일을 넣으면 질문카드가 생성되게 할거야. 그래서 파일 이름도 남편이름_아내이름_재무설계.xlsx 이런 방향으로 넣을거야. 이거 확인하고 어떤식인지 분석해줘" | 기존 기능(AI가 엑셀 글을 읽어 카드 초안 작성)으로는 이 엑셀에서 카드가 0장 나옴. 표 모양이 정해져 있으니 칸을 규칙으로 읽자고 제안 | "근데 구상한 것으로는 재무제표를 넣게되면 그걸 재무설계가사 설계하고, 그 결과를 엑셀로 넣는거라고 생각한건데. 지금 말해주는 부분은 아예 짜주는 것도 AI로 해주는 것 같은 느낌인건가?"라고 되물어 역할을 확인함. **설계는 설계사, 앱은 결과를 읽기만** 하도록 정하고, 숫자는 AI를 거치지 않는 규칙 읽기로 확정 | 재무제표·현금흐름표 엑셀 → 질문 카드 후보(규칙 읽기). 시험 엑셀에서 32항목 중 10개 기본 선택, 금액 전부 엑셀과 일치 |
| 6단계 점검 (앱 — 질문 문구) | "흔들리면 무너지는 것... 이게 의미하는게 뭔지 어렵네." | 카드마다 "이 전제가 흔들리면 무너지는 것" 칸이 있었음. 대체 표현 후보 제시 | 비전공자 팀원이 읽고 이해할 수 있는지를 기준으로 고름. 부부·설계사 화면과 팀 문서를 모두 같은 말로 통일 | "이 계획이 바뀌면 생기는 일" |
| 6단계 점검 (앱 안 AI — 판별 규칙 v2→v3) | (앱 안 AI에 주는 판단 규칙의 일부) "구어체 완화 표현은 유보가 아닙니다. "한 1억 5천?", "1.5억 정도", "2029년쯤"은 그 값을 말한 것입니다." | v2는 20건 중 6건 오판. "한 1억 5천?"의 물음표를 망설임으로 읽는 등 | 오판 6건을 하나씩 읽고 **규칙 탓인 3건만** 일반 규칙으로 고침. 정답이 애매한 3건은 AI에 맞춰 정답을 바꾸지 않고 판정 기준에 따라 재검토 | 판별 규칙 v3. 2건 고쳐지고 1건 틀어짐을 그대로 기록 |
| 6단계 점검 (앱 — 질문 방식) | `【팀 회의 결정 — AI 프롬프트 아님】` 빈 질문 대신 "기존 재무설계 … 지금도 그렇게 생각하시나요?" | AI가 화면·저장 방식을 구현. "그대로예요"를 누르면 계획 값이 그대로 답이 되도록 함 | 질문 방식은 팀이 정했고 AI는 구현만 함. 한쪽으로 쏠리지 않게 두 버튼을 같은 크기로 둠 | 부부 문답 화면 |
| `【팀 작성: 2~5단계】` | | | | |

> 표 아래에 "AI가 낸 첫 제안을 그대로 쓰지 않은 경우" 위주로 골랐다고 한 줄 덧붙이면 양식 취지에 맞다.

## 3. 검증 · 수정 내역

| AI가 제시한 내용 (데이터·수치 등) | 검증 방법 · 확인 출처 | 발견한 문제 | 최종 판단 · 수정 결과 |
|---|---|---|---|
| 판별 AI 정확도: 규칙을 만들 때 본 20건에서 신호등 18/20(90%) | 규칙을 만든 **뒤에** 새로 쓴 10건으로 다시 잼 (정답 세트 대조, `eval/results`) | 같은 20건으로 잰 점수는 규칙이 그 사례에 맞춰져 있어 부풀려짐 | 보고서에는 새 10건의 **80%(신호등) / 70%(중간 판단)**만 씀. AI 없는 단어 겹침 방식은 20% |
| 남편 "1.5억은 받는데 증여세 때문에 차용증" / 아내 "주시는 거예요"를 남편·아내 판단이 서로 뒤바뀐 채 빨강으로 판정 | 최종 신호등과 중간 판단을 **따로** 채점 (혼동행렬 2개) | 신호등은 맞았지만 중간 판단이 틀림. 다른 날 재면 노랑으로 내려가 부부 불일치를 놓침 | 신호등만 보면 못 잡는 오류라 채점 방식을 둘로 유지. "차용증·빌린다는 말이 나오면 금액이 같아도 성격이 다르다"를 다음 규칙 후보로 기록 |
| "남편이 주택자금 절반을 친구 사업에 투자" / "아내는 상의를 못 받았다" → 두 답이 "함께 성립"한다고 판단 | 정답 세트 대조 | AI 오류라기보다 **우리 판단 기준의 빈틈**. 두 사실은 함께 참이지만 두 사람의 입장은 맞서 있음 | 기준을 "사실의 양립"에서 "입장의 양립"으로 바꾸기로 함. 같은 10건으로 다시 재면 시험이 무의미해지므로, 새 사례를 쓴 뒤 잼 |
| 같은 입력 3회 반복 시 결과 30/30 일치 (자기일관성) | 다른 날 같은 조건으로 다시 잼 | 한 번 실행 안에서는 같았지만, 날을 바꾸니 같은 사례가 초록 → 노랑으로 바뀜. 새 10건 점수도 8 ↔ 7로 흔들림 | "한 번 잰 숫자"를 믿지 않기로 함. 제출 전 반복 측정해 **흔들리는 폭을 함께** 적음 |
| (앱 개발) 엑셀에서 질문 카드를 만드는 기능: AI가 엑셀 글을 읽어 카드 초안 작성 | 실제 팀 엑셀을 넣어 봄 | 카드 0장. 지금 숫자만 있는 표라 AI 규칙(현재 사실은 빼기)과 맞지 않음. 숫자를 AI가 옮기는 것 자체도 위험 | 숫자는 AI 없이 규칙으로 옮기도록 바꿈. 32항목을 엑셀 칸과 하나씩 대조해 일치 확인 |

> 마지막 행을 확인하다가 **엑셀 자체의 합계 오류**도 발견했다(고정지출 계 5,091 ≠ 항목 합 5,051, 총유출 10,562 → 10,522). AI 문제는 아니지만, 본문 3단계 재무상태 분석에 쓰는 표라면 고쳐야 한다 — 팀 확인 필요.

## 4. 종합 기술

| 양식 항목 | 쓸 내용 |
|---|---|
| 6단계 중 AI를 가장 유용하게 활용한 단계와 그 이유 | `【팀 작성】` (앱 관점에서는 6단계 점검 — 상담 사이의 변화를 물을 수단을 만듦) |
| AI에 맡기지 않고 본인이 직접 판단한 부분과 그 이유 | `【팀 작성】` + 앱: 계산·판정 기준·재무 조언·재설계는 AI에 맡기지 않음. 엑셀 숫자도 AI를 거치지 않음 (`docs/13` 4·5절) |
| AI 활용이 결과물의 질을 어떻게 높였는지, 근거 | 서술형 답 비교에서 AI 80% vs 단어 겹침 20% (새 10건 기준) |
| 별도로 제출한 앱 — 무엇을 해결하려고, 제작에 AI를 어떻게 | **`docs/13_제출용_앱소개.md` 1·2·8절을 줄여서** (분량이 남으면 3~6절도) |

분량 계산: 부록은 10매가 상한이다. `docs/13` 전체를 그대로 넣으면 약 4~5매다. 팀 부분과 합쳐 넘치면 3·4절(쓰는 방법·설계 원칙)을 반으로 줄인다.
