# 08. 새 부부의 가정 카드, 어떻게 넣을까 (A안·B안)

> 팀 논의 · 2026-10-16 · 11/2 게이트까지 17일
> 결론: **A안으로 간다** (10.16). 카드 템플릿 구성은 `docs/09` 에서 확정한다.

설계사가 새 부부를 등록할 때 그 부부의 설계 전제를 앱에 넣는 방법이 두 가지 있다. 어느 쪽으로 갈지, 그리고 각 안에서 팀이 정해줘야 할 것을 정리했다.

## 지금 상태

새 부부를 등록하면 데모 부부(김현우·박지우)의 카드 10장이 그대로 복사된다.

- 설계 전제 값이 데모 부부의 것이다. 주택가격 6억, 합산 소득 7,600만, 출산 2027년 9월 같은 값.
- "흔들리면 무너지는 것" 문구의 숫자도 데모 부부 기준이다. 소득 상한까지 "여유 900만원"이 대표적.
- 고치려면 설계사가 10장을 하나씩 "두 분께 먼저 묻기"로 바꿔야 한다. 그건 부부에게 확인받는 절차라 첫 입력에는 맞지 않는다.

시연 두 쌍까지는 괜찮지만, 실제 부부에게 쓰려면 둘 중 하나가 필요하다.

## A안 — 설계사가 직접 입력

1. 새 부부 등록하고 입장 코드 발급
2. 카드 템플릿이 한 화면에 나옴. 질문·주제·타입은 채워져 있고 값은 빈칸
3. 설계사가 설계안을 보며 값, 허용 범위, 흔들리면 무너지는 것을 채움
4. 저장하면 v1이 되고 0회차가 열림

| | |
|---|---|
| 덤 | 카드 추가 폼(✅ 10.16 완료), 안 쓰는 카드 빼기 |
| AI | 쓰지 않음 |
| 작업량 | 개발 1일 안팎 |
| 위험 | 낮음 |

- **좋은 점**: "AI는 판별·분류·요약만" 원칙과 충돌 없음 / 심사 시연에서 설계사가 설계안을 넣는 장면이 바로 보임 / B안의 바탕이 됨
- **아쉬운 점**: 부부마다 카드를 손으로 입력 / AI 활용 3번은 보고서에 계획으로만 남음

## B안 — 설계안 문서에서 AI가 초안

1. 설계사가 설계안 문서를 올림
2. AI가 전제를 뽑아 A안 화면을 미리 채움. 칸마다 "AI 초안" 표시
3. 근거 숫자를 못 찾으면 추측하지 않고 "(확인 필요)"로 남김
4. 설계사가 검수·수정하고 저장해야 v1이 됨

| | |
|---|---|
| 전제 | A안이 먼저 있어야 함. 추출 스크립트(`scripts/extract-cards.ts`)는 있음, 텍스트 파일만 |
| AI | 추출·분류만. 계산·조언 없음 |
| 작업량 | A안 + 2~4일 (업로드, 형식 변환, 검수 표시, 추출 정확도 평가) |
| 위험 | 중간. 실제 설계안 샘플이 없으면 시작 불가 |

- **좋은 점**: AI 활용 3번을 실제로 보여줌 / 설계사 입력 시간이 줄어듦
- **아쉬운 점**: 실명·소득이 든 문서를 외부 AI로 보냄, 익명화 필요 / 정확도 숫자를 내려면 정답셋 필요 / 한글(HWP) 파일은 변환이 까다로움

### B안 권장 방식 (10.16 검토)

가상고객 재무제표(`재무제표_.xlsx`)를 보고 정했다. 우리 조의 설계 산출물은 PDF·한글이 아니라 **엑셀**이고, 시트 01(상담 내용)·02(고객정보)가 이미 "목표 영역 / 세부 항목 / 고객 현황 / 체크사항" 표로 정리돼 있다. 그래서 문서 변환이라는 가장 큰 위험이 없다.

**흐름**

1. 설계사가 [설계안에서 뽑기]에서 엑셀을 올린다 (또는 상담 정리 글을 붙여넣는다).
2. 브라우저가 시트 01·02 를 글로 바꾼다. 서버로 가는 건 글뿐이다. 엑셀 파일은 저장하지 않는다.
3. 서버(`api/planner.ts` extract)가 LLM에 **템플릿 28장 목록**과 그 글을 함께 준다. LLM은 두 가지만 한다.
   - **분류**: 이 부부에게 해당하는 템플릿 카드는 어느 것인가.
   - **추출**: 각 카드의 설계 전제 값과 "흔들리면 무너지는 것"을 글에서 그대로 옮긴다. **어느 시트·어느 칸에서 왔는지 출처를 반드시 붙인다.**
4. 결과가 A안 입력 화면을 미리 채운다. 칸마다 "AI 초안 · 출처 01!D9" 표시, 출처 문장은 펼쳐 볼 수 있다.
5. 설계사가 카드마다 확인 체크를 해야 저장된다. 저장된 v1 의 사유는 "최초 설정 (설계안 추출 · 설계사 검수)".

**지켜야 할 선 (CLAUDE.md 절대 규칙과 같다)**

| 규칙 | 뽑기에서의 뜻 |
|---|---|
| AI는 판별·분류·요약만 | 템플릿 슬롯을 고르고(분류) 글에 있는 값을 옮긴다(추출). 새 카드를 지어내지 않는다. 템플릿 밖 전제는 "추가 제안"으로만 따로 보여준다. |
| 계산 금지 | "여유 900만원" 같은 숫자는 글에 그대로 있을 때만 옮긴다. 상한에서 소득을 빼는 계산은 엔진이나 설계사가 한다. |
| 모호하면 추측하지 않는다 | 출처를 못 대면 값은 비우고 "(확인 필요)". 예: 시트 01 은 "서울로 변경", 02 는 "의왕" → 둘 다 출처와 함께 보여주고 비워 둔다. |
| 자동 반영 금지 | 설계사 체크 없이는 card_versions 에 들어가지 않는다. |
| 프롬프트 버전 | `PROMPT_VERSIONS` 에 `extract` 축을 새로 둔다 (v1). |

**왜 자유 추출이 아니라 템플릿 채우기인가**

지금 `scripts/extract-cards.ts` 는 설계안에서 카드를 최대 20장 자유롭게 뽑는다. 그러면 부부마다 카드 key·질문 문구가 달라져 판정 통계와 golden set 이 쌓이지 않고, 질문 문구까지 AI가 지어낸다. 템플릿 채우기로 바꾸면 질문 문구는 팀이 확정한 것 그대로이고, AI는 "해당 여부 + 값 + 출처"만 낸다. 평가도 단순해진다.

**평가 (보고서 숫자)**

- 정답셋: 가상고객 엑셀 1개 → 팀이 28칸 정답(해당 여부·값)을 손으로 채운다. 합성 엑셀 1~2개를 더 만들어 held-out 으로.
- 숫자 3개: 해당 카드 맞힘(재현율·정밀도), 값 일치율, **출처 없는 값 개수(0이어야 함)**.
- `docs/05` 에 판별 평가와 같은 형식으로 한 블록.

**작업량과 순서**

- 전제: 템플릿 28장 확정(`docs/09`) — 슬롯이 곧 템플릿이라 그 전에는 프롬프트를 못 쓴다.
- A안 입력 화면(템플릿 일괄 입력) 1일 → 뽑기 2일(업로드·서버·프롬프트·초안 표시) → 평가 1일.
- 시연만 급하면 1단계를 "글 붙여넣기"로 줄여 반나절 아낀다.

## 한눈에 비교

| | 지금 (데모 복사) | A안 직접 입력 | B안 AI 초안 + 검수 |
|---|---|---|---|
| 부부별 설계 반영 | 안 됨 | 됨 | 됨 |
| 설계사 손 입력 | 없음, 대신 틀린 값 | 카드 전부 | 검수와 수정만 |
| AI 사용 | 없음 | 없음 | 추출·분류 |
| 필요한 것 | 없음 | 템플릿 확정 | A안 + 익명 설계안 샘플 |

| 보고서 서술 | 한계로 적어야 함 | 설계사 입력 흐름 | AI 활용 3번 시연 |

## 팀에 물어볼 것

### A안 — 템플릿을 정하려면 (→ `docs/09`)

1. 기본 카드 구성이 맞나? 빼거나 더할 카드가 있나?
2. "흔들리면 무너지는 것" 문구는 부부마다 숫자가 다르다. 설계사가 직접 쓰나, 앱이 제도 수치로 계산해서 채우나?
   (예: 소득 상한 8,500만원까지 "여유 900만원"은 그 부부의 합산 소득에서 나온다. 앱 계산이면 제도 수치 확인(`docs/07`)이 먼저 끝나야 한다.)
3. 허용 범위 기본값을 이대로 둘까? 지금은 시점 ±6개월, 금액 ±5%, 월 저축액만 ±15%.
4. 첫 입력(v1)은 부부 확인 없이 바로 전제가 되는 것으로 괜찮나? 상담에서 이미 합의한 설계안이라는 전제. 부부 확인 절차는 나중에 값을 바꿀 때만 쓴다.
5. 0회차 3장을 모든 부부에게 고정할까, 부부마다 고를까?

### B안 — 하려면 필요한 것

6. ~~실제 설계안은 어떤 형식인가?~~ → 엑셀로 확인 (10.16, 가상고객 재무제표). 남은 질문: **시트 구성(01 상담 내용 · 02 고객정보)을 다른 조·실제 설계에도 같은 틀로 쓸 수 있나?** 틀이 같으면 뽑기 정확도가 크게 오른다.
6-1. 뽑기 평가용 정답: 가상고객 엑셀의 28칸 정답(해당 여부·값)을 누가 채우나? 합성 엑셀 1~2개를 더 만들 수 있나?
7. 고객 문서를 외부 AI에 보내도 되나? 된다면 이름·연락처 같은 익명화 규칙은 누가 정하나?
8. 보고서에서 AI 활용 3번을 시연으로 넣을까, 공모전 후 계획으로 둘까? 시연이면 "몇 장 중 몇 장을 맞게 뽑았다"는 숫자가 있어야 한다.

## 개발 쪽 제안

- A안은 템플릿이 확정되면 바로 만든다. 1~5번 답이 오면 그대로 반영한다.
- B안은 익명 설계안 샘플이 10월 23일까지 오면 시연용으로 붙인다. 그때까지 없으면 보고서에 공모전 후 계획으로 적는다.
