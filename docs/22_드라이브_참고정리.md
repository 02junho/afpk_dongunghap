# 22. 팀 공유 드라이브에서 앱이 참고할 것 (2026-11-05 읽음)

> 팀 공유 드라이브를 **읽기만** 했다 (드라이브 파일은 고치지 않음). 파일들이 아직 고쳐지는 중이라 **11.05 오후 기준 모습**이다. 다시 읽으면 바뀌어 있을 수 있다.
> 앱 담당이 볼 것만 골랐다. 보고서 본문(1~4단계)은 팀이 쓰는 중이다.

## 1. 지금 고객 이야기 (11.03~04 기준) — 앱의 예시 값이 옛 이야기로 되어 있다

|---|---|---|
| 집 | 서울 광진구 오피스텔 **월세**(보증금 2,000만 · 월 95만) → **2032년 경기 광주 태전지구 60㎡대 매수** | 안양 월세 → 의왕 전세 3억 → 6~7년 뒤 내 집 |

| 부모님 돈 | **없음** (자기자금 표에 부모님 지원이 없다. 시어머니는 양육을 도움) | 남편 측 증여 1억 |
| 출산 | **1~2년 안**, 아내 공백 **약 6개월** | 3년 뒤, 공백 약 2년 |
| 부채 | 자동차 할부 1,130만 원 → **지금 조기상환 제안** | 학자금 · 카드 할부 |

## 3. 앱이 바꾸거나 정해야 할 것 (팀 결정 필요)

1. **질문 틀 칸 바꾸기** — 안 맞는 4칸 대신 지금 계획에 있는 것으로. 후보: 자동차 할부 조기상환 여부 · 출산 · 비상자금 · 청약(신생아 · 신혼부부 특공) 도전 · 아내 노란우산공제 · 주택자금 월 적립액 · 출산전후급여 신청. 질문 틀을 바꾸면 `docs/20` 도 같이 고친다 (CLAUDE.md 규칙).
2. **연도만 있는 날짜** — 계획에 "2032년"만 있다. 지금 규칙은 연 · 월이 다 있어야 받는다 → 설계사가 월을 정해 넣는다. 연도만 받을지 정해야 한다.
3. **매주 금요일 고정** — 11.4 앱 설계에서 "매주 질문은 금요일 고정"으로 정했는데, 지금 앱은 **사이클을 시작한 날부터 7일마다** 연다. 맞춰야 한다.
4. **점검 주기** — 1단계 본문에 "점검은 제안서 제시 후 6개월과 12개월". 앱의 주기를 이 고객은 **반기(6개월)** 로 두면 보고서와 맞는다.
5. **재무설계 결과를 앱에 올릴 때** — 4단계 문서에 "피드백" 탭이 원본과 나란히 들어 있다. 그대로 Word · PDF로 내보내면 같은 내용이 두 번 들어가 AI가 "값이 서로 다르면 비운다" 규칙에 걸린다 → **피드백 탭을 뺀 최종본**을 올린다.
6. **앱 설명 문서가 옛 버전** — 드라이브 "10.27 앱 내용"은 엑셀 카드 · 부부 불일치/전제 폐기 · 자동 점검 101건 시절 글이다. 지금 글은 `docs/13`(제출 글) · `docs/15`(기술서 4번). 또 이 문서 맨 위에 설계사 입장 코드가 적혀 있다 — 공유 드라이브라 팀원 모두 볼 수 있다.
7. **AI 프롬프트 기록장** — 앱 줄이 10.27 기준이다. 11.04 방향 전환 · 11.05 객관식 · 값 찾기(extract) 줄은 `docs/14` 에 있으니 기록장에 옮겨 적으면 된다.
8. **6단계 글이 비어 있다** — 회의록(10.22): "6단계 보고서를 쓸 때 이 앱을 활용하는 방향". 앱 화면과 이야기는 `docs/06` 초안에 있다.

## 4. 팀 문서 안에서 서로 다른 숫자 (팀에 알릴 것 — 앱 문제 아님)

- 아내 연금저축펀드: 노후 문서 월 25만 원 ↔ 통장 쪼개기 표 월 50만 원
- 비상자금: 출산 문서(은행예금 1,500만으로 충당) ↔ 부동산 문서(은행예금 1,130만은 할부 상환, 남은 370만 + 적금 1,500만 = 1,870만) — 출산 문서의 피드백 메모에도 "어디서 꺼내 쓸지 확정해야 함"이 있다
- 보장성보험준비지표: 3단계 3.6%(보험료 연 357만) ↔ 보험 문서 1.1% → 1.7%(개선 후 월 153,988원)
- 아내 소득: 매출 4,000만 / 순사업소득 3,200만 / 월 267만이 섞여 쓰인다
- 비상자금지표: 3단계 본문 9.7배 ↔ 부동산 문서 각주 "6.7배(가이드라인 2배)"
