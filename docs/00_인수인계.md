## 설계사 페이지 = "관리자" 페이지에 대해

맞는 방향이고 이미 그 구조다(`/p/*`). 4화면 전부 만들어 뒀다.

- **UI에서 "관리자"라는 말을 쓰지 않는다.** "설계사 콘솔"로. 심사위원이 재무설계사다.
- **설계사 1명 : 커플 N쌍.** 첫 화면은 `/p/couples` — 커플을 고르면 그게 나머지 화면의 컨텍스트다.
- **커플 발급**도 설계사가 한다 — `/p/couples` 에서 입장 코드 6자리 생성. PWA 홈 화면 추가 안내도 여기서.
- **사용친화의 핵심은 '파일을 안 만진다'는 것.** 카드 1장씩 폼으로, 사유 한 줄 필수, 저장하면 끝.
- 허용 범위 입력은 **타입별로 단위를 다르게** 보여준다 (number ±%, date ±개월).
  한 칸에 0.05와 6을 받으면 반드시 사고가 난다.

## 알려진 구멍

- **SQL 3종이 한 번도 실행되지 않았다.** 첫 적용 때 오류가 날 수 있다. 특히 트리거·뷰·RPC.
- `parseYearMonth`는 "봄/가을", "애 낳고" 같은 표현을 못 푼다 → `unparsed` → 🟡 + 확인 필요(설계사 큐).
  date 카드는 연·월 선택 UI이고, `allowCondition` 카드만 **조건으로 답하는 길**을 남겼다.
  지금은 조건부 답변을 LLM에 넘기지 않는다 — docs/04 §B 결정 대기.
- 금액은 단위 버튼 + 원 단위 미리보기로 입력받는다. 그래도 자유 입력이 오면 모호한 값은 NaN이다.
- 1주차 데모는 **마지막 제출 기기가 브라우저에서 판정**해 sessionStorage 에 둔다. 부부 화면은 안 읽지만
  기기 안에는 있다. 2주차에 서버로 (P0-2).
- mock LLM은 20건 중 4건 맞힌다. 당연함. **품질 측정에 쓰지 말 것** — 베이스라인(키워드 겹침)으로만.
- `eval/run.ts`는 golden의 `cardKey`를 `seed-cards.json`에서 찾는다. 카드 key 바꾸면 golden도 (테스트가 잡아준다).
- 증여재산공제 2년 창구는 조문 L1 미확인. `deadlines.ts` 주석 참조.
- `programs.ts`의 `sourceUrl`이 루트 도메인뿐이다. **심사위원이 재무설계사다** — 고시 페이지
  deep link + 캡처를 `docs/`에 넣고 2026년 기준 수치를 L1에서 재확인할 것 (docs/04 §C).
- `shoot.mjs` 는 playwright 크로미움이 필요하다 (`npx playwright install chromium`). 포트 5180.
