## 다음 할 일 (우선순위)

1. **`.env`에 LLM 키 넣고 `npm run eval`** → `eval/out/v1-*.json` 생성. 이게 부록 3번의 첫 줄이다. 오탐 목록 보고 golden set에 유사 케이스 추가.
2. **Supabase 프로젝트 생성 → `schema.sql` → `seed.sql`** 적용. `.env`에 URL·anon key.
3. **설계사 인증** — Supabase Auth 이메일 로그인. `planners.auth_user_id` 연결. `/p/*`는 로그인 필수, `/c/*`는 커플 코드만.
4. **설계사 화면 실연결** — `/p/cards` 저장 → `card_versions` insert(version+1, reason 필수) → `rounds` kind='reconfirm' 생성. `/p/queue` ← `judgments where verdict='red' and resolved_at is null`.
5. **부부 화면 실연결** — `/c/join` → `members` 매칭. `/c/round` → `answers` insert. 상대 제출 전 잠금은 Realtime 구독(`answers` 테이블 변경 감지).
6. **결과 → judgments 저장** + 🔴면 `planner_summary` 생성(LLM 2차 호출, 3줄).
7. **"이건 같은 뜻이에요"** → `disputes` insert. eval 러너가 disputes를 읽어 golden 후보로 출력하는 기능 추가.
8. RLS. 최소: members는 자기 couple만, answers는 round.status='judged' 전엔 자기 것만 select.
9. 푸시 1회 시연용 (Web Push, VAPID). 반나절 이상 쓰지 말 것.
10. Vercel 배포. 폰 2대로 리허설.

시험기간이 끼면 1·2·3이 쪼개기 쉽다.

## 설계사 페이지 = "관리자" 페이지에 대해

맞는 방향이고 이미 그 구조다(`/p/*`). 단:

- **UI에서 "관리자"라는 말을 쓰지 않는다.** "설계사 콘솔"로. 심사위원이 재무설계사다. 관리자는 IT 운영자처럼 들리고, 설계사는 전문직 사용자다.
- **설계사 1명 : 커플 N쌍.** 콘솔 첫 화면은 커플 목록이어야 한다. 현재 Queue·Cards는 커플 1쌍 고정 → `/p/couples` 추가하고 선택한 커플 컨텍스트로 Queue·Cards 진입.
- **커플 발급**도 설계사가 한다 — `/p/couples/new`에서 코드 6자리 생성 → 부부에게 알려줌. 이게 "설계사 경유 설치"의 시작점이고, PWA 홈 화면 추가 안내도 여기서.
- **사용친화의 핵심은 '파일을 안 만진다'는 것.** 카드 1장씩 폼으로, 사유 한 줄 필수, 저장하면 끝. 이 세 가지가 설계사 UX의 전부다. CMS처럼 키우지 말 것.
- 화면은 4개로 끝: `couples` / `queue` / `cards` / `history`. 3주 안엔 history는 DB만.

## 결정 사항 (바꾸려면 이유를 docs에 먼저)

| 결정 | 이유 |
|---|---|
| PWA, 네이티브 아님 | 심사 장면이 "URL 열고 폰 2대". 설계사 경유 설치라 iOS 홈화면 추가 깔때기가 온보딩에 흡수됨 |
| 3자 비교 (A·B vs 전제) | 2자 비교는 "2029년" vs "애 낳고 나서"를 못 가른다. 전제를 기준점으로 두면 `plan_stale`이 생김 |
| text만 LLM | 환각이 낄 자리를 설계로 줄임. 20장 중 5~6장 |
| 오탐 > 미탐 | 오탐은 사용자가 이의 제기로 잡고 그게 데이터가 됨. 미탐은 조용히 지나감 |
| 카드 버전, md 교체 아님 | 정체성 유지·부분 갱신·설계사가 md 안 씀 |
| 갱신 시 해당 카드만 재합의 | 설계사 수정도 부부 동의를 거쳐야 전제가 됨. 루프가 닫힘 |
| 부대비용 1,200만 명시 필드 | 필요대출 3억 6,248만의 구성. 숨은 가정 금지 |

## 알려진 구멍

- `parseYearMonth`는 "봄/가을", "애 낳고" 같은 표현을 못 푼다 → null → 🟡. 의도된 동작이지만 date 카드 답변 UI를 연·월 선택으로 바꾸면 사라짐. **2주차에 바꿀 것** — 자유 입력은 text 카드만.
- number 카드도 마찬가지. 금액 입력 UI를 숫자 키패드 + 단위 버튼으로.
- mock LLM은 15건 중 5건 맞힘. 당연함. 품질 측정에 쓰지 말 것.
- `eval/run.ts`는 golden의 `cardKey`를 `seed-cards.json`에서 찾는다. 카드 key 바꾸면 golden도.
- 증여재산공제 2년 창구는 조문 L1 미확인. `deadlines.ts` 주석 참조.
