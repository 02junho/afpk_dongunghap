# 06. 보고서 초안 — 앱·AI 부분 (2026-10-25 갱신)

> 팀 보고서의 **앱 설명 + AI 활용 + 부록 3번(AI 비판적 검증)** 에 들어갈 글의 초안. 재무설계 본문(1~5단계)은 다루지 않는다.
> 숫자는 전부 `docs/05_평가기록.md` · `eval/results/*.json` 에서 왔다. 화면은 「화면 흐름도」 PDF(`docs/11`) — 제출 직전에 새 화면으로 다시 찍는다.
> 10.23 팀 회의 결정(질문 방식·재설계 필요·엑셀 카드·정기 주기)과 10.25 카드 틀 확정을 반영했다. 문체는 보고서용으로 다듬기 전이다.

## 1. 무엇을 만들었나 — 한 문장

재무설계사가 세운 설계가 **부부 두 사람에게 지금도 맞는지**, 정기적으로 따로 물어 확인하는 앱(PWA).
설계의 전제를 질문 카드로 만들어 "설계사님과 정한 계획: ○○ — **지금도 그렇게 생각하시나요?**"라고 묻고,
남편의 답 · 아내의 답 · 설계 전제를 **3자 비교**해 어긋난 곳만 설계사에게 올린다.

- 부부는 판정도, 상대의 답도 보지 않는다. **앱은 듣고, 설계사가 말한다.**
- 앱은 전제를 고치지 않는다. 어긋나면 설계사가 **"재설계 필요"**로 표시하고, 다시 설계하는 일은 앱 밖에서 사람이 한다.
- AI는 **판별 · 분류 · 요약**만 한다. 계산 · 재무 조언 · 자동 반영 · 재설계는 하지 않는다.

## 2. 왜 이 형태인가

| 관찰 | 설계로 답한 것 |
|---|---|
| 설계는 "전제"의 묶음인데, 전제는 부부 각자의 머릿속에 다르게 저장된다 ("1억 지원"이 한쪽엔 증여, 한쪽엔 빌린 돈) | 전제를 **질문 카드**로 쪼개 하나씩 묻는다. 카드 틀은 주제 10개 · 28장 (가상고객 재무제표로 만들고 10.25 팀 확정) |
| 서로 답을 보면 맞춰 쓴다 | **블라인드** — 상대 답은 끝까지 안 보인다. 대기 화면은 진행 개수만 |
| 빈 질문("언제 집을 사실 계획인가요?")은 무엇과 비교할지 흐리다 | 설계사와 정한 **계획을 먼저 보여주고** "지금도 그런가요?"로 묻는다. 바뀌었으면 바뀐 값을 적는다 |
| "같은 말인가"만 보면 틀린다 ("2029년" vs "애 낳고 나서") | **설계 전제를 기준점**으로 둔 3자 비교 → *부부 불일치*와 *전제 폐기*를 가른다 |
| 시연 대상은 정해진 가상고객이고, 설계를 바꾸는 건 설계사의 일이다 | 앱 안에서 전제를 바꾸지 않는다. 어긋남 → **재설계 필요** → 앱 밖에서 다시 설계 |
| 설계사는 상담 내용을 엑셀(재무제표 양식)로 정리한다 | 그 엑셀에서 **AI가 질문 카드 초안**을 만들고, 설계사가 카드마다 확인해 고른 것만 저장한다 |
| 정기 점검인데 날짜가 고정 문구였다 | 마지막 맞춰보기 + **3개월**로 다음 날짜를 계산해 보여준다 |

## 3. 화면 — 부부 5 · 설계사 4

**부부(폰, 홈 화면에 추가해 앱처럼 사용)**
입장(설계사가 보낸 카톡 안내문 또는 QR → 코드 · 남편/아내) → 홈([내 설계] 주제별 펼치기 / [맞춰보기] "이제부터 시작할게요")
→ 문답(계획 카드 + "네, 그대로예요 / 아니요, 바뀌었어요" → 바뀐 값. 금액은 단위 버튼, 시점은 연·월 또는 "조건으로 답하기", 선택형은 "기타 — 직접 입력")
→ 대기(상대 진행 개수만) → 전달됨("답변이 등록되면 설계사님께서 연락을 주실 거예요" · 다음 맞춰보기 날짜).

**설계사(노트북)**
부부 목록(코드 발급 · 카톡 안내문 복사 · 입장 QR · 이름 고치기 · 빈 카드로 시작) → 처리 대기(🔴 + 확인 필요, AI 3줄 요약, 버튼 3개)
→ 질문 카드(카드 추가 · 재무제표 엑셀로 만들기 · 폰에 나가는 모양 미리보기) → 변경 이력.

## 4. 판정 — 무엇을 AI가 하고, 무엇을 안 하나

### 4.1 답의 형태 4가지 중 AI는 하나

| 형태 | 비교 | 예 |
|---|---|---|
| 금액 · 나이 | 허용 비율(±%) 안이면 🟢, 두 배 안이면 🟡, 넘으면 🔴 — **규칙** | 목표 주택가격 5억 |
| 시점 | 허용 개월 — **규칙** | 주택 취득 2031년 3월 |
| 선택 | 같은 보기인가 — **규칙**. "기타 — 직접 입력"은 비교하지 않고 설계사 확인으로 | 육아휴직 주체 |
| 서술 | **AI 의미 비교** | 승진·이직 계획, 양가 지원, 투자 성향 |

"네, 그대로예요"는 설계 전제 값이 그대로 답이 된다 — 규칙상 🟢. 바뀐 값만 비교 대상이 된다.
AI 비중이 작은 것은 의도다 — 환각이 재무설계에 끼어들 자리를 설계로 줄였다.
해석하지 못한 답(모호한 금액, 조건부 시점, 보기에 없는 답)은 추측하지 않고 "확인 필요"로 설계사에게 간다.

### 4.2 3자 비교

```
남편 답 vs 전제 → 같음 / 조금 다름 / 크게 다름      아내 답 vs 전제 → 같음 / 조금 다름 / 크게 다름      두 답이 함께 성립하는가
```

| 남편 | 아내 | 두 답 | 판정 |
|---|---|---|---|
| 같음 | 같음 | 성립 | 🟢 합의 |
| 조금 다름 포함 | | | 🟡 다음 맞춰보기에 다시 (어느 화면에도 안 뜸) |
| 크게 다름 포함 | | 성립 | 🔴 **전제 폐기** — 부부는 같은 생각, 설계가 낡음 |
| 크게 다름 포함 | | 모순 | 🔴 **부부 불일치** |
| 2회 연속 🟡 | | | 🔴 승격 |

"전제 폐기"가 이 구조의 핵심이다. 부부가 다투는 게 아니라 **설계가 현실을 못 따라온 경우**를 따로 잡아 설계사에게 보낸다.
설계사는 처리 대기에서 **재설계 필요 / 상담 때 다루기 / 이건 같은 뜻이에요(AI 오판 표시)** 중 하나로 닫는다.

### 4.3 AI가 하는 일 3개 / 하지 않는 일

| 하는 일 | 입력 | 출력 | 지키는 선 |
|---|---|---|---|
| ① 서술형 답의 의미 비교 | 전제 + 남편 답 + 아내 답 | 편차 2개 + 성립 여부 + 사유 한 문장 | 서술형 카드에만. 숫자·시점·선택은 규칙 |
| ② 🔴·확인 필요 건 설계사용 요약 | 카드 + 두 답 + **이미 나온 판정** | 3줄 (사실 / 영향 / 확인할 질문) | 판정을 바꾸지 못한다. 조언·계산 없음 |
| ③ 재무제표 엑셀 → 질문 카드 초안 | 엑셀 칸의 글 (파일은 저장 안 함) | 카드 초안 + 출처(시트·칸) | 엑셀에 적힌 값만 옮김. 상대 시점("3년 뒤")·서로 다른 값은 비우고 메모. 출처 없는 카드는 버림. **설계사가 카드마다 확인해야 저장** |

하지 않는 일: 계산(규칙 엔진), 판정 기준(설계사가 카드에 적음), 재무 조언(어떤 문장도 부부에게 가지 않음), 자동 반영, 재설계.

③의 첫 시험(팀 재무제표 양식, 10.23): 20초, 초안 15장, 출처 15/15, 바로 저장할 수 있는 카드 8장.
나머지 7장은 일부러 비워 둔 칸이다 — 희망 지역이 시트마다 "의왕"과 "서울 광진구"로 달라 비우고 두 값을 메모했고, "6~7년 이내"는 날짜로 바꾸지 않았다.
추출 정확도(정답 대비)는 엑셀 양식이 확정된 뒤 잰다.

## 5. 부록 3번 — AI를 어떻게 검증했나 (① 의미 비교)

### 5.1 방법

- **정답 세트 30건**: 답변쌍 + 정답 라벨(최종 신호등 + 중간 라벨 3개). 라벨끼리 모순이면 테스트가 잡는다.
- **혼동행렬 2개**: 신호등(3×3)과 편차(3×3)를 따로 채점한다. 최종 신호등만 보면 중간 라벨이 틀렸는데 운으로 맞은 경우를 못 가른다.
- **자기일관성**: 같은 입력을 3회 돌려 흔들림을 기록한다. 현재 모델은 무작위성 설정(temperature)을 받지 않으므로 고정할 수 없고, 측정만 할 수 있다.
- **대조군**: AI 없이 단어 겹침으로 답하는 방식. "의미 비교에 AI가 필요한가"의 근거.
- **미학습 집합**: 프롬프트 규칙을 만든 **뒤에** 쓴 10건으로 다시 잰다. 규칙을 만들 때 본 20건의 점수는 과적합이 섞여 있다.

### 5.2 결과 (2026-10-14, Claude Sonnet 5.5, 각 3회)

| | 신호등 | 중간 라벨 | 두 답 성립 여부 | 자기일관성 |
|---|---|---|---|---|
| 대조군(단어 겹침) · 30건 | 6/30 (20%) | 19/60 (32%) | 10/30 | — |
| 프롬프트 v2 · 20건 | 16/20 (80%) | 35/40 (88%) | 17/20 | 20/20 |
| 프롬프트 v3 · 30건 | 26/30 (87%) | 52/60 (87%) | 28/30 | 30/30 |
| **프롬프트 v3 · 미학습 10건** | **8/10 (80%)** | **14/20 (70%)** | 9/10 | 10/10 |

보고서에 쓰는 숫자는 **미학습 10건의 80% / 70%** 다. 대조군 대비 4배.
10.18 같은 조건으로 1회 다시 재었을 때 미학습 10건이 7/10 이었다 (`docs/05`). 10건에서 1건은 10%p — 제출 전에 3회 반복으로 다시 재고 **흔들림 폭을 함께** 적는다.

### 5.3 v2 → v3: 무엇을 고쳤고 무엇이 나빠졌나

v2 오판 6건을 읽고 **프롬프트 탓인 3건만** 일반 규칙으로 고쳤다 (케이스를 지목하지 않음):
① 구어체 완화("한 1억 5천?")는 유보가 아니다 ② 부분적 제안("일부는 ETF 해도")은 뒤집은 게 아니라 흔들린 것 ③ 전제에 합의가 있으면 합의가 선호보다 기준.
결과: 2건 맞아지고 **1건 틀어짐**. 라벨이 다툼의 여지가 있는 3건은 모델에 맞춰 고치지 않고 규칙서 기준으로 재검토했다.

### 5.4 미학습 10건에서 배운 것

- **오탐이 미탐보다 많다** (설계 의도). 부서 이동을 "변화"로 읽어 🟡 — 처리 대기엔 안 가고 다음 맞춰보기에 다시 묻는다.
- **"두 답이 함께 성립하는가" 정의의 구멍**: "남편이 주택자금 절반을 친구 사업에 투자" / "아내는 상의 못 받았다" — 두 문장은 동시에 참이라 '성립'으로 읽혔다. 설계사가 보려는 건 사실의 양립이 아니라 **입장의 양립**이다. → 프롬프트 v4 후보. 단 같은 10건으로 재면 더는 미학습이 아니므로, 새 케이스를 쓴 뒤 잰다.
- **실행 간 흔들림**: 한 실행 안의 자기일관성 30/30이 실행 간 일관성을 보장하지 않았다 (같은 케이스가 오전 🟢, 오후 🟡). 경계 케이스는 날을 달리해 두 번 잰다.

### 5.5 오탐이 데이터가 되는 구조

설계사가 처리 대기에서 **[이건 같은 뜻이에요]** 를 누르면 그 건이 따로 기록된다. 재무설계사가 직접 표시한 오탐 — 정답 세트의 가장 좋은 재료다.
어느 프롬프트 버전이 판정했는지가 모든 판정에 남으므로, 버전을 올릴 때마다 같은 집합으로 다시 잴 수 있다.

## 6. 솔직한 한계

- **계획을 먼저 보여주는 질문**은 "그대로예요"로 답하기 쉽게 만든다 (팀이 고른 방식). 두 버튼을 같은 크기로 두고, 바뀐 경우를 놓치지 않는지는 리허설에서 본다.
- 엑셀 → 질문 카드는 **엑셀 양식이 아직 확정 전**이라 정확도를 재지 않았다. 초안은 설계사 확인 없이는 저장되지 않는다.
- **빈 카드로 시작한 부부**는 아직 맞춰보기를 열 수 없다 — 첫 맞춰보기가 연습용 카드 3장(집 시점 · 승진·이직 · 양가 지원)으로 열린다. 설계사가 물어볼 카드를 골라 여는 기능은 보류.
- 맞춰보기 주기는 모든 부부 3개월로 고정. 다음 맞춰보기는 설계사가 연다 (자동으로 열리지 않음). 알림 대신 설계사가 카톡으로 알린다.
- 설계사 로그인은 공용 코드 하나(임시). 부부는 입장 코드 + 익명 로그인.
- 한국어 뉘앙스("좀 무리" vs "감당 가능")는 AI도 흔들린다. 정답 세트에 일부러 넣어 기록했다.
- 제도 수치(소득 상한 · 한도 · 금리)는 한 곳에 출처 · 확인일과 함께 두었다. 1차 출처 재확인은 제출 전 필수.

## 7. 기술 (한 줄씩)

Vite + React PWA(홈 화면 추가, 새 배포 자동 반영) / Supabase(Postgres · 행 단위 보안 · 익명 로그인) / Vercel(서버 함수만 AI · DB 열쇠를 쥠, 브라우저엔 열쇠 없음) /
Claude Sonnet 5.5 / 자동 점검 95건 · 실제 DB 처음부터 끝까지 시험 39단계 / 부부는 상대 답 · 판정을 읽을 권한 자체가 없다 — 블라인드는 화면의 선의가 아니라 DB가 보장한다.
