## 1. 무엇을 만들었나 — 한 문장

재무설계 6단계 "재무설계안 점검"에서, 재무설계 결과가 부부 두 사람에게 지금도 맞는지 6주에 걸쳐 따로 묻고 계획과 다른 답만 설계사에게 올리는 앱(PWA).

- 질문 틀은 모든 고객이 같다 — 6테마(주택 · 출산/육아 · 노후 · 보험 · 부채 · 투자) × 5문항 = 30문항. 고객마다 다른 것은 계획 값뿐이고 재무설계 결과에서 채운다.
- 매주 한 테마씩 5문항, 6주가 한 사이클. 6주가 끝나면 설계사가 상담을 요청하고 고객에 따라 분기 · 반기마다 다시 돈다.
- 부부는 판정도, 상대의 답도 보지 않는다. 앱은 듣고, 설계사가 말한다.
- AI는 재무설계 결과에서 계획 값 찾기 · 말로 적은 답 뜻 비교 · 요약만 한다. 계산 · 재무 조언 · 자동 반영 · 재설계는 하지 않는다.

## 2. 왜 이 형태인가

| 관찰 | 설계로 답한 것 |
|---|---|
| 설계는 계획의 묶음인데, 계획은 부부 각자의 머릿속에 다르게 저장된다 ("1억 지원"이 한쪽엔 받는 돈, 한쪽엔 빌린 돈) | 계획을 30문항으로 쪼개 하나씩 묻는다 |
| 6단계 점검은 모든 고객에게 같은 항목을 봐야 빠짐이 없다 | 질문 틀을 고정하고 계획 값만 고객마다 바꾼다. 무엇을 물을지 설계사가 매번 고르지 않는다 |
| 30문항을 한 번에 물으면 지친다 | 매주 한 테마 5문항 · 6주. 답하지 않은 주는 닫지 않고 다음 주로 넘기고 4일 지나면 늦은 분에게만 한 번 더 알린다 |
| 서로 답을 보면 맞춰 쓴다 | 블라인드 — 상대 답은 끝까지 안 보인다. DB 권한으로 막았다 |
| 계획을 보여 주고 "지금도 그렇게?"로 물으면 "네"를 누르기 쉽다 | 계획 값은 보여 주지 않고 목표를 묻는다 — "은퇴 후 한 달 생활비는 얼마를 원하나요?" 두 분이 같은 목표를 기억하고 있는지가 드러난다 |
| 보기를 계획 값에서 만들면 답을 알려 주게 된다 | 보기는 모든 고객에게 같은 목록. 숫자 질문은 만 원 · 세 · 개월 단위로 적는다. 그래서 외워서 답할 수 있는 목표만 묻는다 (보장성 보험료 153,988원 같은 계산 결과는 "늘린다 / 유지 / 줄인다" 보기로) |
| 고정 틀이라 어떤 고객에게는 맞지 않는 질문이 있다 (아이 계획이 없는 부부의 출산 질문) | 건너뛰지 않고 정답지에 "해당 없음" 을 넣는다. 나중에 계획이 생기면("1~2년 안") 그것도 "계획과 다름"으로 잡힌다 |
| 재무설계 결과와 조금이라도 다르면 설계가 달라진다 | 허용 범위 없음. 한 분이라도 계획과 다르면 🔴 "계획과 다름" |
| 설계사는 재무설계 결과를 문서로 정리한다 | 재무설계 결과를 올리면 AI가 30칸의 계획 값을 찾고 설계사가 칸마다 원문과 대조해 확인한 것만 저장한다 |

## 4. 판정 — 무엇을 AI가 하고, 무엇을 안 하나

### 4.1 답은 보기 · 숫자, AI는 말로 적은 답만

| 답 | 비교 | 예 (계획: 은퇴 후 생활비 월 300만 원) |
|---|---|---|
| 숫자 적기 | 계획 값과 같은지 — 규칙 | 300 → 🟢 · 350 → 🔴 |
| 보기 고르기 | 같은 보기인지 — 규칙 | 주택자금 두는 곳: 계획 "절반씩" ↔ 답 "투자 위주" → 🔴 |
| 아직 모름 · 해당 없음 | 계획 값과 같은지 — 규칙 | 계획이 "해당 없음"이면 "해당 없음"만 🟢 |
| 말로 적기 — 값만 적음 | 규칙이 읽는다 ("3백", "월 350") | |
| 말로 적기 — 말이 섞임 | AI가 계획과 같은 뜻인지 본다 | "지금이랑 비슷하게요" |

예전의 "다른 답 후보"(계획 값의 0.5~1.5배 등)는 쓰지 않는다 — 계획 값을 숨기는데 후보가 계획에서 나오면 답을 알려 주게 된다. 모든 질문에 "아직 모름" · "해당 없음" · "말로 적기"가 있다. "해당 없음"은 설계사만 정답지에 넣는다 — 문서에 값이 없다고 AI가 "해당 없음"으로 판단하지 않는다.
AI 비중이 작은 것은 의도다 — 환각이 재무설계에 끼어들 자리를 설계로 줄였다.

### 4.2 판정은 하나 — 계획과 다르면 다른 것

```
남편 답 vs 계획 → 같음 / 다름        아내 답 vs 계획 → 같음 / 다름
```

| 남편 | 아내 | 판정 |
|---|---|---|
| 같음 | 같음 | 🟢 — 설계사에게 올라가지 않음 |
| 한 분이라도 다름 (금액 1만 원 · 나이 1살 · "아직 모름"도 · 정답지가 "해당 없음"인데 다른 답도) | | 🔴 계획과 다름 — 처리 대기 |
| 말로 적은 답을 읽지 못함 | | 🟡 확인 필요 — 추측하지 않고 설계사에게 |

예전에는 부부끼리 다른 경우(부부 불일치)와 부부는 같은데 계획이 낡은 경우(전제 폐기)를 나눴다. 팀 기준("재무설계 결과와 다르면 다른 것")에 따라 하나로 합쳤다. 설계사 화면에 계획 · 남편 · 아내 값이 나란히 보이므로 (계획 300만 · 남편 300만 · 아내 350만), 기억 차이인지 · 한 분의 생각이 바뀐 것인지 · 둘 다 바뀐 것인지는 설계사가 판단한다.
설계사는 처리 대기에서 확인함(메모 선택)으로 닫는다. AI가 판정한 건에만 이건 같은 뜻이에요(AI 오판 표시)가 있다.

### 4.3 AI가 하는 일 3개 / 하지 않는 일

| 하는 일 | 입력 | 출력 | 지키는 선 |
|---|---|---|---|
| ① 재무설계 결과에서 계획 값 찾기 | 재무설계 결과 문서의 글 (파일은 저장 안 함) | 30칸마다 문서 표기 그대로 + 근거 문장 | 원 단위 · 연월로 바꾸는 건 규칙. 상대 시점("3년 뒤")은 날짜로 바꾸지 않음. 근거 문장이 문서에 없으면 표시. 설계사가 칸마다 "원문과 맞음"을 눌러야 저장 |
| ② 말로 적은 답의 뜻 비교 | 계획 + 남편 답 + 아내 답 | 각 답이 계획과 같음 / 조금 다름 / 크게 다름 + 사유 | 말이 섞인 답에만. 고른 답 · 숫자 · 값만 적은 답은 규칙 |
| ③ 🔴 · 확인 필요 건 설계사용 요약 | 카드 + 두 답 + 이미 나온 판정 | 3줄 (무엇이 다른지 / 영향 / 확인할 질문) | 판정을 바꾸지 못한다. 조언 · 계산 없음 |

하지 않는 일: 계산(규칙 엔진), 판정 기준(팀이 정함 — 허용 범위 없음), 재무 조언(어떤 문장도 부부에게 가지 않음), 자동 반영, 재설계.

①의 정확도(정답 대비)는 재무설계 결과 샘플을 받은 뒤 30칸 정답표와 대조해 잰다 — 아직 재지 않았다.

## 5. 부록 3번 — AI를 어떻게 검증했나 (② 뜻 비교)

### 5.1 방법

- 정답 세트 30건: 말로 적은 답변쌍 + 정답 라벨(각 답이 계획과 같음 · 조금 다름 · 크게 다름 + 최종 신호등). 라벨끼리 모순이면 테스트가 잡는다.
- 두 가지를 따로 채점: 최종 신호등과 중간 판단(각 답 vs 계획)을 따로 본다. 신호등만 보면 중간 판단이 틀렸는데 운으로 맞은 경우를 못 가른다.
- 자기일관성: 같은 입력을 3회 돌려 흔들림을 기록한다. 현재 모델은 무작위성 설정(temperature)을 받지 않으므로 고정할 수 없고 측정만 할 수 있다.
- 대조군: AI 없이 단어 겹침으로 답하는 방식. "뜻 비교에 AI가 필요한가"의 근거.
- 미학습 집합: 프롬프트 규칙을 만든 뒤에 쓴 10건으로 다시 잰다.

### 5.2 결과 (Claude Sonnet 5.5, 미학습 10건)

| | 최종 신호등 | 중간 판단 (각 답 vs 계획) |
|---|---|---|
| 대조군 (단어 겹침) | — ¹ | 5/20 (25%) |
| 프롬프트 v3 (10.14, 3회) | 9/10 (90%) | 14/20 (70%) |
| 같은 조건 다른 날 (10.18, 1회) | 9/10 | 15/20 (75%) |

¹ 새 판정에서는 정답 🔴 가 많아(10건 중 7건) "모두 🔴"로 찍기만 해도 신호등이 7/10 이 된다. 그래서 대조는 중간 판단으로 한다.

보고서에 쓰는 숫자는 미학습 10건의 신호등 90% · 중간 판단 70%(대조군 25%) 다. 30건 전체로는 신호등 28/30.
11.05 판정 규칙을 바꾸면서 프롬프트는 그대로 두고 이미 나온 AI 답을 새 규칙으로 다시 채점했다 (AI를 다시 부르지 않음 — `docs/05` 11.05 블록). 예전 규칙에서는 미학습 신호등 8/10 이었다.

### 5.3 v2 → v3: 무엇을 고쳤고 무엇이 나빠졌나

v2 오판 6건을 읽고 프롬프트 탓인 3건만 일반 규칙으로 고쳤다 (케이스를 지목하지 않음):
① 구어체 완화("한 1억 5천?")는 유보가 아니다 ② 부분적 제안("일부는 ETF 해도")은 뒤집은 게 아니라 흔들린 것 ③ 계획에 합의가 있으면 합의가 선호보다 기준.
결과: 2건 맞아지고 1건 틀어짐. 라벨이 다툼의 여지가 있는 3건은 모델에 맞춰 고치지 않고 판정 기준에 따라 재검토했다.

### 5.4 판정 규칙을 바꾸며 배운 것

- 남은 오판 2건은 모두 오탐(같은 뜻을 "조금 다름"으로) — 부서 이동을 "변화"로 읽은 것 등. 예전엔 🟡로 넘어갔지만 이제 🔴로 설계사에게 간다. 설계사가 "이건 같은 뜻이에요"로 바로잡는다. 원하는 쪽의 실패다.
- 예전 미탐 1건이 사라졌다. "1.5억은 받는데 증여세 때문에 차용증" / "주시는 거예요"를 다른 날 "조금 다름"으로 읽어 🟡로 놓쳤던 건이, "조금 다름도 다름"이 되면서 🔴로 잡힌다.
- 실행 간 흔들림: 한 실행 안의 자기일관성 30/30이 실행 간 일관성을 보장하지 않았다 (같은 케이스가 오전 🟢, 오후 🟡). 경계 케이스는 날을 달리해 두 번 잰다.
- AI가 보는 답의 모양이 바뀌었다. 보기 · 숫자로 답하게 되면서 AI는 "월 300만 원", "2032년" 같은 짧은 계획 값과 말로 적은 답을 비교한다. 이 모양의 정답 사례를 더 써서 따로 재야 한다 (다음 할 일).

### 5.5 오탐이 데이터가 되는 구조

설계사가 처리 대기에서 [이건 같은 뜻이에요] 를 누르면 그 건이 따로 기록된다. 재무설계사가 직접 표시한 오탐 — 정답 세트의 가장 좋은 재료다.
어느 프롬프트 버전이 판정했는지가 모든 판정에 남으므로, 버전을 올릴 때마다 같은 집합으로 다시 잴 수 있다.

## 6. 솔직한 한계

- 계획 값을 보여 주지 않으므로 기억이 달라도 🔴 가 된다. 이것이 목적(같은 목표를 기억하는지)이지만 허용 범위도 없어 처리 대기 건수가 늘 수 있다. 설계사는 계획 · 남편 · 아내 값을 나란히 보고 "확인함"으로 빠르게 닫는다.
- 외워서 답할 수 있는 목표만 물을 수 있다. 계산 결과(보장성 보험료 153,988원 등)는 숫자 대신 보기(늘린다 / 유지 / 줄인다)로 물어 금액의 작은 변화는 놓친다.
- 고정 틀이라 해당 없는 질문도 묻는다 (아이 계획이 없는 부부에게 출산 질문). "해당 없음"을 누르는 수고가 있지만 건너뛰지 않기 때문에 나중에 새로 생긴 계획도 잡힌다.
- 재무설계 결과에서 값 찾기는 재무설계 결과 양식(파일 형식 포함)이 아직 정해지기 전이라 정확도를 재지 않았다. 찾은 값은 설계사 확인 없이는 저장되지 않는다.
- 부부는 홈의 [내 설계]에서 재무설계 결과(계획 값)를 볼 수 있어, 답하기 전에 확인하고 답할 수도 있다. 고객이 자기 계획을 볼 수 있어야 한다고 보고 팀이 그대로 두었다 (11.09).
- 폰 알림은 아이폰에서 홈 화면 아이콘으로 열었을 때만 받는다(iOS 16.4 이상). 실제 폰 수신은 팀 테스트에서 확인한다.
- 설계사 로그인은 공용 코드 하나(임시). 부부는 입장 코드 + 익명 로그인.
- 제도 수치(소득 상한 · 한도 · 금리)는 한 곳에 출처 · 확인일과 함께 두었다. 1차 출처 재확인은 제출 전 필수.
