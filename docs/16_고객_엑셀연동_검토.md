# 16. 고객이 직접 엑셀을 고치게(연동) 할 수 있나 — 검토

> 팀장님 질문 (2026-11-04): "지금은 설계사만 엑셀을 넣을 수 있는데, 집안 사정이 바뀌면 **고객이** 엑셀을 고치게 할 수 있을까? 매번 고쳐서 저장하고 올리는 게 아니라 **연동**으로."
> **11.04 결정: 고객이 엑셀을 고치는 방향은 하지 않는다. 아래 "대신 제안" 두 가지를 만들었다** (`docs/00` 11.04 반영).
> 쓰려면 DB 패치 `supabase/patch-2026-11-04-change-notices.sql` 을 한 번 실행해야 한다.

## 한 줄 답

**기술적으로는 가능하지만, 고객이 엑셀(설계안)을 직접 고치게 하는 건 추천하지 않는다.**
대신 같은 목적을 앱 안에서 이루는 방법이 있다. 부부 홈에 **"바뀐 게 있어요"** 버튼을 두는 것이다. 그리고 설계사 쪽 엑셀 연동(다시 올리지 않고 "다시 읽기")을 같이 붙인다.

## 팀장님이 원하는 것

1. 이직, 임신, 부모님 지원 취소처럼 **집안 사정이 바뀌면 고객이 바로 알리고 싶다.** 설계사가 맞춰보기를 열 때까지 기다리지 않고.
2. **파일을 고치고, 저장하고, 다시 올리는 번거로움을 없애고 싶다.**

두 목적 모두 맞다. 문제는 "고객이 엑셀을 고친다"는 **방법**이다.

## 고객이 엑셀을 고치면 생기는 문제

| # | 문제 | 왜 중요한가 |
|---|---|---|
| 1 | **설계사의 계획이 사라진다** | 엑셀은 설계사가 세운 설계안이다. 고객이 고치면 "원래 계획"이 없어진다. 앱은 남편 답 · 아내 답 · **원래 계획** 셋을 비교하는데, 기준이 사라지면 비교가 안 된다. 팀 결정 Q2("전제는 앱 안에서 바꾸지 않는다")와도 맞지 않다 |
| 2 | **부부가 서로 고친 걸 보게 된다** | 한 파일을 둘이 같이 쓰면 남편이 고친 걸 아내가 바로 본다. "두 사람에게 따로 묻고, 결과는 설계사만 본다"는 원칙(10.14 팀 결정)이 깨진다. 한쪽이 몰래 고치거나, 고친 걸 보고 다툴 수 있다 |
| 3 | **누가 언제 무엇을 바꿨는지 남지 않는다** | 앱은 값을 덮어쓰지 않고 바뀐 기록을 모두 남긴다. 엑셀은 저장하면 예전 값이 사라진다 |
| 4 | **고객 휴대폰에서는 연동이 거의 안 된다** | 아래 표 |

연동 방법별로 고객 입장에서 보면:

| 방법 | 고객 휴대폰에서 | 문제 |
|---|---|---|
| 내 컴퓨터 파일 연결 | **안 된다** (크롬 · 엣지 **컴퓨터**에서만 됨) | 부부는 폰으로 앱을 쓴다 |
| 구글 시트 링크 | 된다 | "링크 있는 사람 누구나 보기"로 열어야 해서 **고객 재무정보가 새어 나갈 수 있다.** 부부 둘 다 같은 시트를 본다 |
| 엑셀 온라인(OneDrive) | 된다 | 마이크로소프트 로그인 연결이 복잡하다. 고객마다 계정이 필요하다 |

폰에서 엑셀 표를 고치는 것 자체도 불편하다. 고객마다 엑셀을 다루는 실력도 다르다.

## 대신 제안: 부부 홈의 "바뀐 게 있어요"

```
고객(한 사람)                         설계사
─────────────                        ─────────
홈 → [내 설계] → 카드 옆
"바뀐 게 있어요"
   ↓
바뀐 내용 입력                         처리 대기에
(맞춰보기와 같은 화면:          →      "고객이 먼저 알린 변화"로 올라옴
 금액 단위 버튼, 연·월, 기타)              ↓
   ↓                                 확인 → ① 상대 배우자에게도 물어보기(맞춰보기 열기)
"설계사님께 전달됐어요"                      ② 재설계 필요
(배우자에게는 안 보임)                      ③ 상담 때 다루기
                                         ↓
                                     계획을 바꾸면 설계사가 엑셀을 고치고,
                                     앱에는 새 버전으로 기록 (예전 값도 남음)
```

- **팀장님 목적 1을 이룬다:** 고객이 기다리지 않고 바로 알린다.
- **팀장님 목적 2를 이룬다:** 고객은 엑셀을 만지지 않는다. 앱에서 버튼 하나로 끝난다.
- **원칙을 지킨다:** 계획은 설계사가 바꾼다. 배우자에게는 안 보인다. 기록이 남는다.
- **AI는 쓰지 않는다:** 한 사람만 알린 것이라 셋을 비교할 수 없다. 판정 없이 그대로 설계사에게 알림으로 간다.

## 설계사 쪽 엑셀 연동은 따로 (전에 정리한 안)

설계사가 계획을 고칠 때 파일을 다시 올리지 않게 하는 방법이다.

- **내 컴퓨터 파일 연결 + 바뀐 것만 반영** (추천): 처음 한 번 파일을 연결해 두면, 이후에는 엑셀을 저장하고 앱에서 **"다시 읽기"**만 누른다. 앱이 "남편 급여 6,700만 → 7,200만, 반영할까요?"처럼 바뀐 것만 보여 준다. 설계사 컴퓨터(크롬 · 엣지)에서 쓰니 이 방법이 맞다.

두 가지를 합치면 이렇게 된다.

> 고객이 앱에서 "바뀐 게 있어요" → 설계사가 확인하고 엑셀을 고침 → 앱에서 "다시 읽기" → 카드에 새 값 반영.
> **고객도 설계사도 파일을 다시 올리지 않는다.**

## 만드는 데 드는 것 (대략)

| 기능 | 할 일 | 기간 |
|---|---|---|
| 부부 "바뀐 게 있어요" | 부부 화면 1개, 설계사 처리 대기에 표시, 데이터베이스에 표 1개 추가 (SQL 패치를 한 번 실행해야 함) | 하루 + 시험 |
| 설계사 "다시 읽기" + 바뀐 것만 반영 | 파일 연결, 기존 카드와 비교 화면, 새 버전 저장 | 하루~이틀 + 시험 |

제출 전에 만들지, 보고서에 **"다음 단계"**로만 적을지 정해야 한다.

## 팀장님께 확인할 것

1. **고객이 바꾸고 싶은 게 "계획"인가, "지금 숫자"인가?**
   - 계획: 집 살 시점, 출산 계획, 부모님 지원 같은 것 → 위 제안으로 된다.
   - 지금 숫자: 예금 잔액, 이번 달 지출 같은 것 → 가계부 연동에 가까운 다른 이야기다. 지금 앱의 범위("계획이 지금도 맞는가")를 넘는다.
2. **고객이 알린 변화를 배우자에게 보여 줄까?** 추천은 "보여 주지 않음"이다. 지금 원칙과 같다.
