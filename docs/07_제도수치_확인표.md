# 07. 제도 수치 확인표 (docs/04 §C)

`src/engine/programs.ts` · `deadlines.ts` 에 박힌 숫자를 **1차 출처(L1)** 에서 다시 확인하고, 확인한 페이지 주소와 날짜를 코드에 적는다.
심사위원이 재무설계사다 — 카드와 엔진이 같은 숫자를 말해야 하고, 그 숫자는 출처를 찍을 수 있어야 한다.

## 어디서 확인하나

| 제도 | L1 출처 | 찾을 것 |
|---|---|---|
| 신혼부부전용 구입자금 | 주택도시기금 **기금e든든** / nhuf.molit.go.kr → 주택구입자금 → 신혼부부전용 구입자금 | 대출대상(소득·순자산·혼인기간), 대출한도, 대상주택(가격), 금리표 |
| 신생아 특례 디딤돌 | 같은 사이트 → 신생아 특례 구입자금 | 소득(맞벌이 합산·1인), 순자산, 한도, 주택가격, 금리, **출산 기준일·접수 기한** |
| 혼인·출산 증여재산공제 | 국세법령정보시스템 → 상속세 및 증여세법 **제53조의2** | 혼인신고일 전후 **2년**, 한도 1억 (출산 포함 통합 한도) |
| 대출 접수 시점의 금리 | 기금e든든 공지 (금리는 분기·정책에 따라 바뀜) | 확인일 기준 금리 밴드 |

## 확인 뒤 할 일

1. 값이 다르면 `programs.ts` 의 숫자를 고치고 **같은 줄에** `sourceUrl`(deep link)·`verifiedOn`(확인일)을 갱신한다.
2. `npm test` — 숫자가 바뀌면 엔진 테스트(세 개의 벽·월 상환액)가 깨진다. 테스트의 기대값과 **카드 stake 문구**
   (`seed-cards.json`·`seed.sql`: "여유 900만원", "한도 부족 4,248만") 를 같이 고친다.
3. 확인한 페이지를 PDF 로 저장해 `docs/sources/` 에 둔다 (파일명: `2026-10-xx_신혼부부전용_구입자금.pdf`).
4. 보고서(docs/06 §6)의 "L1 재확인은 제출 전 필수" 줄을 "확인 완료(날짜)" 로 바꾼다.

값이 **같아도** 1·3·4 는 한다 — 지금 `sourceUrl` 은 루트 도메인뿐이라 심사위원이 바로 찍어볼 수 없다.
